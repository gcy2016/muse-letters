# 噜噜岛开发约定

给以后接手的 Claude（新对话、Claude 小号）看的。每个新对话都会通过 CLAUDE.md 读到这份。

## 一、显示物件的位置统一写在布置表 `layout.js`

噜噜岛和噜噜之家里所有“显示物件”（挂画、相框、天气 / 日历小屏、快递盒、地图、岛上的牌子和灯……）摆在哪，**只写在 `layout.js`**，不要在别的文件里写死坐标或墙的名字。以后搬家、换位置、改户型，只改这一个文件。

- **房子里**（`HOUSE`）：用房子自己的坐标，写 `pos`（中心位置，米）、`facing`（正面朝哪边）、大小。挂在哪面墙、属于哪个房间，程序按位置自动算（`house.addItem(obj, { auto: true })`），墙被剖开削矮时一起藏起来。
- **岛上**（`ISLAND`）：挂在房子上的写相对房子的坐标（`onHouse: true`），房子在岛上挪位置时跟着走。
- **新加显示物件**：做成正面朝 +z、原点在中心的一个 Group，在 `layout.js` 里加一行位置，用 `placeInHouse(house, obj, LAYOUT.xxx, "点击id")` 放进房子（岛上用 island.js 里的 `islandPlace`）。
- **跟着家具走的**：电视画面、玄关留言板（软木板）贴在模型里的家具上，挪家具在 `tools/build_house.py` 里改，它们自动跟着。
- **改了户型**（`tools/build_house.py`）以后：检查布置表里房子里的位置还在不在墙上、在不在原来的房间里。
- **楼层**：房子支持多层。`build_house.py` 的户型表里房间写 `level=1` 就在二楼，墙、家具、地板、位置点自动抬到那层；`house.js` 按楼层分开显示（看哪层就藏起上面的楼层）。布置表里楼上的东西直接写楼上的高度（`pos` 的 y = 那层地面高 + 离地高度），程序按高度判断在哪层。新写的代码不要假定房子只有一层（比如角色能站哪、碰撞框，都要看楼层）。房间按钮、角色出生位置不要写死房间名，从 `house.rooms`、`house.levels` 读，角色出生位置写在布置表的 `PET_SPOTS`。

## 一·五、岛上的代码不要都堆在 `island.js`

加新设施（游乐园、花园……）时单独写成文件（几个设施合一个文件也行，不用一个设施一个文件），`island.js` 只负责引进来、按布置表放好。拆分不能让首页变慢：大的模型等需要时再下载。详细说明在 `island.js` 开头。

## 二、私密内容不能明文放进仓库

仓库是公开的。照片、快递、日程这类私密内容，用**大门锁密码**加密后再放（`lock.js`）：
- 照片：`photo-lock.html` 生成加密文件，放 `assets/house/photos/`，挂在哪写在 `layout.js` 的 `PHOTO_SLOTS`。
- 快递、日历：Muse 在对应页面加密后发帖。

## 三、Claude 和 Muse 不在留言板上互动

留言板（`[留言]` 帖子）只给 Claude 小号（工作流，github-actions[bot]）、小miu、lulu 用。对话里的 Claude 要找 Muse 办事，直接在仓库发 issue（标题不加 `[留言]`），开头署名「Claude留言」，下一行以 `/小miu` 开头（和 MUSE.md 留言规则的写法一样，Muse 的哨兵看整个仓库，按这个唤醒；@Muse 叫不醒）。要新发 issue，改旧帖正文不会唤醒。Muse 在 issue 下回复。要不要 Claude 回复，由噜噜小兵另外说。
留言板网页和玄关软木板也只显示小号的 Claude 帖子：用 gcy2016 发、署名「Claude留言」的帖子不显示（`app.js`、`board-feed.js`）。
